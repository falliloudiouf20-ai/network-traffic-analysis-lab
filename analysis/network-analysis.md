# Network Traffic Analysis

## 1. ICMP Traffic Analysis

### Objective

The objective of this first capture is to observe and analyze ICMP traffic generated by a ping between the Kali Linux workstation and the local network gateway.

### Environment

- Operating System: Kali Linux
- Capture interface: `wlan0`
- Source IP: `10.245.154.105`
- Destination IP: `10.245.0.1`
- Protocol analyzed: ICMP
- Tool: Wireshark

### Test Performed

The following command was executed from the Kali Linux terminal:

```bash
ping -c 4 10.245.0.1
The command generated four ICMP Echo Requests toward the gateway.

The terminal output showed:

4 packets transmitted
4 packets received
0% packet loss
Minimum RTT: 1.964 ms
Average RTT: 2.184 ms
Maximum RTT: 2.420 ms
Wireshark Analysis

The capture was performed on the wlan0 interface.

The following Wireshark display filter was used:

icmp

The capture shows two types of ICMP packets:

Echo (ping) request
Echo (ping) reply

The observed communication was:

10.245.154.105 → 10.245.0.1
ICMP Echo Request

10.245.0.1 → 10.245.154.105
ICMP Echo Reply

The requests and replies are visible in the Wireshark packet list, confirming bidirectional ICMP communication between the Kali workstation and the gateway.

Security Interpretation

ICMP is commonly used for network diagnostics and connectivity testing. In this controlled test, the traffic is considered normal because it was intentionally generated using the ping command.

The successful Echo Replies indicate that the gateway was reachable from the Kali workstation during the capture.

From a security monitoring perspective, ICMP traffic can also be useful during network reconnaissance. A high volume of ICMP requests or systematic ICMP probing across multiple hosts could indicate network discovery activity.

However, the current capture only contains a small number of intentional ICMP packets and does not provide evidence of malicious activity.

Evidence

The Wireshark capture is documented in:

screenshots/icmp-capture.png

The screenshot shows:

the icmp Wireshark filter;
the source and destination IP addresses;
ICMP Echo Requests and Echo Replies;
the successful ping results from the Kali terminal.
Conclusion

The first network capture successfully demonstrated normal ICMP communication between the Kali Linux workstation and its network gateway.

The capture provides a baseline example of legitimate network traffic that can later be compared with potentially suspicious traffic.
## 2. DNS Traffic Analysis

### Objective

The objective of this capture is to observe a DNS query generated by the Kali Linux workstation and analyze the corresponding DNS response.

### Test Performed

The following command was executed:

```bash
dig example.com

The query requested an IPv4 address (A record) for example.com.

The DNS resolver used by the system was:

DNS server: 10.245.0.1
Port: 53
Transport protocol: UDP
Query type: A
Query status: NOERROR
DNS Response

The DNS server returned two IPv4 addresses for example.com:

172.66.147.243
104.20.23.154

The measured query time was:

4 ms
Wireshark Analysis

The traffic was captured on the wlan0 interface using the following display filter:

dns

The capture shows the complete DNS exchange:

10.245.154.105 → 10.245.0.1
DNS Standard query
A example.com

10.245.0.1 → 10.245.154.105
DNS Standard query response
A example.com
172.66.147.243
104.20.23.154

The matching query and response identifiers confirm that the response corresponds to the DNS request generated by the Kali workstation.

Security Interpretation

DNS is essential for translating domain names into IP addresses. The observed traffic represents normal DNS resolution initiated by the workstation.

From a security monitoring perspective, DNS traffic can provide valuable information about potentially suspicious activity. Examples include unusual domains, high query volumes, repeated failed queries, randomly generated domain names, or abnormal query patterns.

In this controlled test, the query was intentional and targeted the well-known example.com domain. No suspicious behavior was identified.

## 3. TCP Traffic Analysis

### Objective

The objective of this capture is to observe the establishment of a TCP connection generated by an HTTPS request.

### Test Performed

The following command was executed:

```bash
curl -I https://example.com

This command initiates a TCP connection over HTTPS (TCP port 443) and retrieves only the HTTP response headers.

Wireshark Analysis

The capture was performed on the wlan0 interface.

The following Wireshark display filter was used:

tcp.flags.syn == 1

The capture shows the beginning of the TCP three-way handshake:

Client (10.245.154.105)
        │
        │ SYN
        ▼
Server (104.20.23.154)
        │
        │ SYN, ACK
        ▼
Client

Observed packets:

SYN
SYN, ACK

Destination port:

443 (HTTPS)

The server responding to the connection attempt was:

104.20.23.154

The HTTP response returned:

HTTP/2 200 OK

confirming that the TCP connection was successfully established and that the HTTPS request completed successfully.

Security Interpretation

TCP is the transport protocol used by most Internet applications.

The SYN packet initiates a connection, while the SYN/ACK packet confirms that the destination server is reachable and accepts the connection request.

Monitoring TCP handshakes is an essential activity for SOC analysts because abnormal numbers of SYN packets, incomplete handshakes, or repeated connection attempts may indicate reconnaissance activity, port scanning, or denial-of-service attacks.

In this capture, the TCP exchange is legitimate and corresponds to a user-generated HTTPS request.

Evidence

The screenshot shows:

the SYN packet;
the SYN/ACK packet;
the destination HTTPS port (443);
the curl -I https://example.com command;
the successful HTTP/2 200 response.
Conclusion

The capture successfully demonstrates the establishment of a legitimate TCP connection over HTTPS.

This analysis provides a baseline example of normal TCP communication that will later be compared with suspicious network behavior during the investigation phase.
